## 6. 并发安全验证

### 6.1 请假审批并发控制

**机制：** 乐观锁（`stateVersion` 字段）

**测试场景：**
- 两个审批人同时审批同一请假单 → 仅一个成功，另一个收到 `LEAVE_STATE_CONFLICT` 错误
- 审批期间申请人撤回 → 审批操作返回状态冲突

**验证方式：** 后端集成测试 `day4-leave.test.ts`

### 6.2 负责人操作并发控制

**机制：** 数据库唯一约束 + 事务

**测试场景：**
- 同时为同一部门任命两个不同负责人 → 数据库约束保证一致性

**验证方式：** 后端集成测试 `day2.test.ts`

## 7. 安全检查

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 密码哈希存储 | ✅ | 使用 bcryptjs，salt rounds = 10 |
| HttpOnly Cookie | ✅ | JWT 存储在 HttpOnly Cookie 中，前端 JS 不可读取 |
| CORS 配置 | ✅ | 仅允许指定来源，`credentials: true` |
| Helmet 安全头 | ✅ | 使用 helmet 中间件设置安全 HTTP 头 |
| 输入验证 | ✅ | 使用 class-validator / zod 进行请求参数校验 |
| SQL 注入防护 | ✅ | Prisma ORM 参数化查询，无原生 SQL 拼接 |
| 密码字段不返回 | ✅ | API 响应中不包含 `passwordHash` 字段 |
| 角色权限控制 | ✅ | 每个接口都有角色检查中间件 |
| 强制改密 | ✅ | 新用户首次登录必须修改密码 |
| Token 失效机制 | ✅ | `tokenVersion` 递增使旧 Token 立即失效 |
| 生产环境密钥强制配置 | ✅ | `NODE_ENV=production` 时未设置 JWT_SECRET 会启动失败 |
