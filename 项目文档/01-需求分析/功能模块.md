## 功能模块

公告管理

| 项目     | 示例                                                         |
| -------- | ------------------------------------------------------------ |
| 模块名称 | 公告管理                                                     |
| 模块职责 | 完成公司公告的发布、查阅和阅读情况追踪                       |
| 主要功能 | 草稿创建／编辑／删除、发布、撤回、公告查询与详情、已读记录、阅读情况查询 |
| 使用角色 | 管理员维护公告并查看阅读情况；员工和负责人查阅公告           |
| 关键边界 | 只能编辑草稿；已发布公告不可修改；首次打开详情记录已读       |
| 优先级   | V1 必须完成，但核心请假闭环优先                              |

请假管理

| 项目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 模块名称 | 请假管理                                                     |
| 模块职责 | 完成请假申请、审批、撤销、进度与结果查询，保留完整业务记录   |
| 主要功能 | 提交申请、天数计算与规则校验、确定审批人、本人申请查询与详情、撤销申请、待办审批、通过／驳回、历史处理查询 |
| 使用角色 | 员工管理本人申请；部门负责人同时处理分配给自己的申请；管理员不参与 |
| 关键边界 | 不能自行审批；仅待审批可撤销；提交后不可编辑或删除；驳回必须说明原因；最终状态不可更改；本人待审批或已通过申请的日期不能重叠 |
| 优先级   | V1 必须完成，属于核心业务闭环，优先实现                      |

账号与个人信息

| 项目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 模块名称 | 账号与个人信息                                               |
| 模块职责 | 管理账号访问与个人资料，支持账号创建、密码维护和停用         |
| 主要功能 | 登录／退出、首次登录改密、个人资料查询、联系方式修改、密码修改、账号创建、密码重置、账号启用／停用 |
| 使用角色 | 所有角色维护本人资料与密码；管理员创建和管理账号             |
| 关键边界 | 不开放注册；登录账号唯一且不可修改；首次登录或密码重置后必须改密；本人只能修改工作邮箱、联系电话和密码；账号不删除；停用后已有登录也不能继续访问；密码修改或重置后原登录状态失效；管理员不能停用自己 |
| 优先级   | V1 必须完成，身份认证和权限控制是其他业务的基础              |

部门与员工管理

| 项目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 模块名称 | 部门与员工管理                                               |
| 模块职责 | 维护组织结构、员工归属和部门负责人                           |
| 主要功能 | 部门查询、新增／改名／删除、员工查询、姓名与职务维护、部门调整、角色变更、负责人分配／更换 |
| 使用角色 | 管理员维护                                                   |
| 关键边界 | 单层部门，名称唯一；员工和负责人必须属于一个部门；每部门最多一名本部门启用负责人；更换后原负责人恢复为员工；存在关联账号或历史申请的部门不能删除；员工有待审批申请，或负责人有本人待审批申请或未处理任务时，禁止相关调动、角色变更及停用 |
| 优先级   | V1 必须完成，部门与负责人信息是请假审批的前提                |

企业通讯录

| 项目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 模块名称 | 企业通讯录                                                   |
| 模块职责 | 帮助员工查找同事及工作联系方式                               |
| 主要功能 | 人员列表、按姓名搜索、按部门筛选、查看人员信息               |
| 使用角色 | 员工和部门负责人查阅                                         |
| 关键边界 | 仅展示启用员工和负责人；展示姓名、部门、职务、工作邮箱及联系电话；停用账号和独立管理账号不展示；不公开请假等私有信息；不提供修改他人资料的能力 |
| 优先级   | V1 必须完成，在人员基础信息可用后实现                        |

工作概览

| 项目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 模块名称 | 工作概览                                                     |
| 模块职责 | 汇总当前角色关心的信息，并提供相关业务入口                   |
| 主要功能 | 员工查看未读公告数量、本人待审批数量和最近申请结果；负责人额外查看待本人审批数量；管理员查看启用员工及负责人总数、部门数量和公告草稿数量；进入对应业务 |
| 使用角色 | 所有角色，按角色展示不同内容                                 |
| 关键边界 | 统计与实际记录一致；仅展示有权查看的信息；刷新后更新即可；不要求实时推送或复杂图表；不在概览中重复建设业务管理功能 |
| 优先级   | V1 必须完成，在相关业务与数据可用后实现                      |

### 模块职责衔接

- **账号与个人信息**负责账号访问、密码和联系方式；**部门与员工管理**负责组织归属、角色及人事资料，两者使用同一份人员信息。
- **通讯录**展示已有人员资料，不另行维护一份通讯录数据。
- **工作概览**汇总其他模块的数据，并进入对应业务，不独立维护统计结果。
- 权限校验、异常处理、分页及加载反馈属于各模块共同遵守的要求，不建设独立权限配置中心。

|---|---|
| 模块名称 | 内部知识分享 |
| 当前状态 | 开发中 |
| 模块职责 | 沉淀和检索操作指南、技术经验、工作复盘 |

| 优先级 | V1 增量必须完成 |
